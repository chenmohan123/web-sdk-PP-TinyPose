# Compatibility

[简体中文](../zh-CN/compatibility.md)

The 0.3.0 desktop acceptance dated 2026-09-18 runs at least 30 changing frames for each of three models × WASM/WebGPU × main/Worker. It records model/actual backend, 17 finite keypoints, load count, maximum concurrency and late-result checks after pause/stop. The [report](../../reports/2026-09-17-media/media-acceptance.json) includes actual browser, OS and build digests. The 12 combinations use a separate acceptance page with the same Demo controller and production SDK assets; the production Demo UI separately exercises default-configuration local video and Chromium fake-device camera input. The fixture translates/scales a still photo and is not an action dataset. Neither fake-device nor 390px testing verifies physical cameras or phones.

The fixed-tensor model probe passed WASM/WebGPU × main/worker on 2026-09-16 with Windows 11 (10.0.26200), Chromium 153.0.8010.12, i5-10400F, NVIDIA Blackwell, and ORT Web 1.27.0. Each combination used 32 person crops; WASM used one thread and no explicit fallback. Evidence is in `reports/2026-09-16-feasibility/`.

Separate [SDK acceptance](../../reports/2026-09-16-feasibility/sdk-browser.json) passed on 2026-09-17 in the same desktop environment, using all four combinations and 32 fixed RGBA images with person regions. It exercises browser preprocessing, inference, DARK, and original-image coordinate restoration, plus a JPEG Blob smoke test per combination, cancellation/recovery, cache behavior, and lifecycle handling. The report includes model and final SDK/ORT asset digests. [Demo acceptance](../../reports/2026-09-16-feasibility/demo-browser.json) covers upload, region selection, language switching, and the 390px layout.

Fixed-tensor probes and SDK image processing are verified separately and do not substitute for each other. Full COCO keypoint AP, other browsers, phones, WeChat web-view, and WebNN/NPU are unverified. The 390px check is a desktop viewport check only. Feature detection is not a compatibility promise; an unavailable GPU adapter must report UNSUPPORTED.

The default 256×192 FP32 model in 0.1.0 passed full GET and checksum verification from both fixed Hub sources on 2026-09-17; see the [historical distribution receipt](../../reports/2026-09-17-release/distribution-weights-verified.json). Its historical release acceptance covered one model × two sources × two backends × two execution modes, for eight combinations tied to that build. This evidence is limited to that version's distribution and browser-inference scope. Source-switch regressions use controlled delays and do not independently prove remote inference.

Version 0.2.0 covers 128×96 FP32, retained 256×192 FP32, and 128×96 W16A32 in the same desktop environment. All 12 numeric and runtime combinations across WASM/WebGPU × main/Worker passed; see the [browser comparison](../../reports/2026-09-17-variants/browser-comparison.json). W16A32's maximum reliable-point difference across backends was `0.001567px`. All three models and cards passed full GET at fixed revisions from both Hubs; see the [variant distribution receipt](../../reports/2026-09-17-variants/distribution-variants-verified.json). The 24 real combinations across three models × two sources × two backends × two execution modes also passed against the 0.2.0 build; see the [release acceptance receipt](../../reports/2026-09-17-variants/distribution-browser.json).
