# TinyPose 视频与摄像头设计

2026-09-17 用户确认：TinyPose 下一阶段先本地视频、再摄像头，完成桌面验收后发布目标 0.3.0。单 SDK 保持独立；人体检测组合属于门户未来 Workflow。

## 分层与范围

这是 Demo 媒体调度子系统。现有 `createTinyPose`、`PoseInput`、`run`、17 点原图坐标和模型资产均保持兼容；runtime 不获取摄像头权限、不依赖 DOM 媒体或 React。Demo 将视频帧读为 RGBA，使用既有公开 SDK 推理。

方案采用 Demo 独立媒体控制器和视图，共享一个有背压的单帧循环。将媒体调度放进 SDK 会增加 DOM 依赖；分别写视频和摄像头循环会重复取消和生命周期逻辑，因此不采用。每次媒体会话只创建一个 SDK 实例，连续帧复用；同一控制器最多一个未完成推理，不积压旧帧。

本轮三个模型不重新转换、上传或修改 URL/SHA。默认仍 256×192 FP32、ModelScope、CPU/WASM、Worker。可显式切换三模型、双源、CPU/GPU、主线程/Worker，不静默回退。

## 用户体验

Demo 沿用 Detection 的工作台布局、令牌、图标和中英文切换，增加图片/视频/摄像头三个标签。图片流程、示例与框选保持可用，媒体模式隐藏图片专用控件与图片示例。新增控件只表达状态和命令，不增加操作说明段落。

- 视频：选择本地视频，读取首帧预览，播放识别、暂停、单帧识别、停止；时间轴支持暂停后定位，显示当前位置和时长。支持浏览器能解码的本地格式，解码失败明确报错。
- 摄像头：用户点击开启才申请 `getUserMedia({video:true,audio:false})`；开启后实时识别，可暂停/继续、单帧识别、停止。停止须停止全部自有轨道；不申请音频，不上传媒体。没有设备、拒绝权限、设备占用或不安全上下文均报告可理解的错误。
- 调度：最大处理帧率选项 5/10/15/30，默认 15；显示实测处理 FPS、已处理帧、主动跳过帧与采集/单帧耗时。主动跳过计数只计调度器实际观察且未处理的新帧，不冒充摄像头硬件丢帧。
- 框选：在媒体暂停且当前帧有效时框选固定原图像素区域；清除框选恢复整帧。框不自动跟随人体。切换输入源或尺寸变化清除原框，拖动进度保留同一视频的固定框。框选控件留在预览上方，切换状态不推动预览。
- 预览：显示采样帧和对应的原图坐标骨架；结果不能画在不对应的后续帧或新输入上。没有结果时可显示当前采样帧。暂停、seek、输入替换先清除失效结果。
- 页面隐藏或 pagehide 停止调度并释放摄像头轨道；回来不自动申请权限/恢复。卸载、模型/来源/后端/执行模式切换、重置和清缓存都取消旧任务并释放旧实例，晚到的权限结果必须停止轨道。

## 生命周期

媒体控制器拥有视频元素的当前对象 URL、MediaStream、帧回调、AbortController 和 SDK 实例。关闭源时先递增 generation，使晚到的解码、权限、加载、推理结果失效；取消帧调度并停止媒体，再释放实例。`dispose` 幂等。

单帧推理输入是独立拥有的 RGBA，不把下一帧覆盖到正在推理的 buffer。使用 requestVideoFrameCallback，在不支持时用 requestAnimationFrame 与 currentTime 去重；忙时跳过，空闲再采当前最新帧，不排队保存帧。暂停取消结果接收并等待在途工作结束后允许 step/恢复；Worker 或主线程具体取消时机沿用 SDK，不宣称主线程 GPU 内核可立即中断。

媒体 load 只在开始推理前进行一次。暂停可以保留会话；停止、清理或配置切换释放会话。清缓存须等待媒体退出，避免旧下载完成重新写入缓存。拒绝未 ready、零尺寸和非有限时间等输入。

错误区分媒体读取/解码、CAMERA_UNSUPPORTED、CAMERA_PERMISSION、CAMERA_UNAVAILABLE、MEDIA_PLAYBACK 和 SDK 原错误码。新加载尝试清除旧错误，失败不能伪装为 ready；资源释放失败必须可观察，不能悄悄成功。

## 验收与发布

- 行为单测覆盖单并发、忙时跳过、FPS 限制、暂停与在途推理、停止后晚到结果、晚到摄像头权限、URL/轨道/回调释放、seek/模型切换失效。
- 浏览器 UI 回归覆盖视频首帧/播放/暂停/seek/step/停止/替换、固定框、相机拒绝和晚到授权、隐藏/卸载、三模式切换、双语、桌面和 390px 布局。摄像头使用 Chromium 可控 fake-device 做媒体管线验证，明确不是物理摄像头/手机验收。
- 使用已有公开人物示例生成标明来源的短视频测试资产，不引入无许可素材；视频帧必须变化。真实桌面 SDK 连续帧验证三模型 × WASM/WebGPU × main/Worker，共 12 组合，检查有限 17 点、实际后端、连续结果变化、最大在途数 1、停止后无新结果；全片不宣称动作质量或自动跟踪。
- 可复用媒体测试素材及归属说明跟随测试放在 `tests/fixtures/media`；运行回执、截图和统计放在 `reports/2026-09-17-media`，不覆盖已发布历史证据。
- 正式生产构建仍以三模型 × 双源 × 双后端 × 双执行模式 24 组合验收并绑定最终资产；沿用完整 GET 的模型分发证据，不重复上传权重。新增媒体脚本输出日期、环境、运行范围、失败与资产摘要，不手写通过。
- 文档完整双语，更新六组指南、manifest、示例和 CHANGELOG，清楚区分 SDK 单帧能力与 Demo 媒体适配。目标 package 0.3.0，模型版本仍 0.1.0/0.2.0。
- 用户已有 PR/合并/达标发布/本轮已合并分支清理授权。通过审查和 CI 后发布不可变 v0.3.0、npm、Release、Demo；回读公开包、Pages、线上媒体基本流程。门户只同步真实版本和媒体 Demo 能力，运行检查后 PR 合并。保留用户文件与旧工作树。

手机、微信、物理摄像头、NPU、全量 COCO AP、多人检测、自动跟踪和平滑均没有本轮验证承诺。
