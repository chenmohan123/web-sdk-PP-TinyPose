## 目标与选择

先完成一个模型的正确推理与原图坐标关键点展示，支持单人图或调用者明确提供的人体框。用户已同意 2D 检测阶段收口；此阶段交付新增的姿态能力。

选择官方增强版 `tinypose_enhance/tinypose_256x192` FP32。固定 PaddleDetection `b25522a0f4bde8c80603f3ba5e3472059972e3b5`；该版本 TinyPose 专页列出 256×192 与 128×96 均约 1.32M 参数，COCO val GT 人体框 AP 分别为 68.3 与 58.4。该官方指标不是本地重测结果，更不能直接代表浏览器自动多人流程。

取舍：128×96 计算更少，可在首版完成后按收益评估；256×192 更适合先建立定位基线。首版采用外部框/单人图，避免同时新增人体检测权重和跨 SDK 调度。自动多人检测、跟踪、动作识别、视频平滑、FP16/量化和 NPU 均不属于本次首版。

## 来源和许可

使用官方 ZIP：`https://bj.bcebos.com/v1/paddledet/models/keypoint/tinypose_enhance/tinypose_256x192.zip`。ZIP 地址可能变动，因此记录 ZIP、内部文件和 ONNX 的字节数、SHA-256，并固定源码与配置。源码仓库为 Apache-2.0，官方模型表关联此部署资产；保留 LICENSE、作者与预处理/后处理归因。部署 ZIP 没有额外的独立权重许可文件，应如实注明“官方仓库许可及模型发布归属”，不把训练集来源当成另一份模型许可。

生产来源仍为 ModelScope/Hugging Face，默认 ModelScope。发布前必须先上传固定版本并完整 GET 回读核对。当前本地可行性产物仅从本机服务加载，不虚构 Hub revision、公开 URL 或已上线状态。npm 不包含 ONNX 权重。

## 模型边界与数学路径

- 输入 `float32 [1,3,256,192]`，RGB，按官方配置 `/255`、mean `[0.485,0.456,0.406]`、std `[0.229,0.224,0.225]`。
- 原始 ONNX 支持动态 batch；首版 API 固定一次处理一个人体。主要输出 `float32 [1,17,64,48]` 热力图；辅助 argmax 输出不替代 DARK。
- 有人体框时按固定官方 `expand_crop` 扩展 30%，处理宽高比、整数裁剪和图像边界；坐标变换元数据必须与真实采样对应。
- 无人体框时将整张图作为单人裁剪图；不声称自动找到或分离多人。
- 保留部署配置 `TopDownEvalAffine` 的路径，不能把训练使用的 UDP 自动套到部署预处理。
- DARK 使用 3×3 高斯平滑、对数热力图与二阶局部细化；还原到原图像素坐标。中心取整遵循参考路径，奇数尺寸须测试。
- 固定 COCO 17 点顺序、名称和骨架连线。`score` 是未校准热力图响应，不能当作可见性/遮挡分类或概率。低分点由显示阈值控制，原始输出保留；不人为截断到图像边界。

## 公共接口

运行时与 React 无关，输入为 RGBA 像素或 Blob。工厂 `createTinyPose(options)` 返回 `load`、`run`、`dispose` 与 manifest/capabilities；`run({ image, region? }, { signal? })` 返回关键点、裁剪映射、实际后端、执行模式和分项耗时。`region` 为原图像素 `{x,y,width,height}`。

现有 Detection 的公开 `Detection.box` 包含相同四字段，但这不等同于端到端组合已验证。后续宿主须从模型标签映射确认 person 类，复用同一解码方向/坐标系，保持单个在途任务，并明确两个 SDK 的资源释放责任。

错误码区分参数、清单、下载、摘要、环境不支持、会话、推理、忙碌、取消和已释放。并行 run 拒绝为 BUSY；取消检查覆盖下载、会话完成及推理完成边界。ORT 无法保证中断已提交 GPU/CPU 内核，主线程取消丢弃结果并释放临时资源，不能声称立即停止硬件执行。dispose 幂等，等待或终止实例拥有的任务并释放 Worker/会话。

WASM 与 WebGPU 显式选择，失败不静默回退。main/worker 均由同一数学实现生成结果；Worker 只转移 SDK 拥有的缓冲区，保留调用者像素。缓存按模型身份和摘要隔离，回读校验完整性；清理功能限定本 SDK 命名空间，不能清理其他 SDK/站点数据。

## Demo 与示例

独立中文默认 React Demo，支持英文切换、图片输入、手工框选人体、CPU/GPU、main/worker、运行/取消/清理。图片与骨架同屏展示，使用共享 UI tokens；将性能与模型信息收纳在次要区域，避免大量操作说明挤下结果。390px 不横向溢出。提供 Vanilla 示例；多人自动检测不嵌入此单 SDK Demo。

本地首版明确标注未发布，使用本地模型；正式版准备双来源时才显示有效来源选择。包含当前模型与本 SDK 全部缓存清理、隐私说明、模型/运行时/耗时标记。上传图片留在浏览器，不发往远程识别服务。

## 验收门槛

1. 固定来源、ONNX 检查与 Paddle 参考；同输入热力图最大绝对误差 ≤0.0001，高响应点（Paddle score≥0.2）原图坐标误差 ≤0.1px。该门槛检验转换一致性，不是识别质量 AP。
2. 固定 RGBA 输入单独验证浏览器预处理与 Python OpenCV，覆盖奇数尺寸、边缘框、宽框、窄框和非零偏移；不得把预制张量验证说成完整 SDK 验证。
3. 桌面 WASM/WebGPU × main/worker 真实图片端到端运行，取消/恢复、重复加载、缓存回读/损坏、释放等生命周期验证。GPU 不可用时明确 unsupported。
4. 构建、类型检查、单测、SDK 标准前后检查、浏览器 smoke；证据记录模型摘要、浏览器、OS、GPU、ORT 和日期。
5. 本地验证只声明本机范围；缺少全量关键点 AP、移动端、WebNN 证据时明确标注。正式发布还需双 Hub 完整回读、公开仓库治理、CI、npm/Release/正式 HTTPS Demo 验收及门户登记。

## 与旧规划的关系

按任务拆 SDK 的边界不变，2D 检测转稳定维护。此处将旧文档“可见性结果”澄清为本模型实际可提供的响应分数，属于基于模型事实收紧输出承诺。Workflow 仍需真实用例、输入输出兼容与资源生命周期证据，不能因当前有四个已发布 SDK 就自动视为满足条件。
